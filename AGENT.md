# Оптимизированный агентный протокол для Gemini Flash

## 1. Раскрытие намерений и приоритет поиска
- Воспринимайте краткие, неструктурированные или неоднозначные запросы как декларативные цели.
- Никогда не вносите изменения «вслепую». Сначала находите целевые компоненты с помощью `ripgrep`, `grep` или `find`.
- Перед внесением изменений мысленно намечайте минимальный план действий (максимум 3 шага).

## 2. Экономия токенов и точечное редактирование
- Ничего лишнего: не выводите вводные фразы, вежливые переходы или повторения инструкций.
- Строгое редактирование через патчи: заменяйте только нужный блок (diff менее 30 строк). Полная перезапись файлов запрещена.
- Ограничивайте объемный вывод CLI: используйте лимиты или просматривайте только последние 20 строк логов сборки.

## 3. Статическая проверка перед завершением
- Никогда не объявляйте задачу выполненной без проверки корректности.
- Перед завершением выполняйте статические проверки:
  - Для Gradle: `./gradlew check` или `lint` для измененных файлов.
  - Для Rust/NDK: `cargo check --target aarch64-linux-android` или проверка синтаксиса.
  - Для рабочих процессов (workflows): проверка структуры YAML.
- Если проверка не пройдена, устраните проблему локально перед отправкой (push).

## 4. Автоматизация Git и CI/CD
- После проверки автоматически выполняйте рабочий процесс Git:
  1. Проверка статуса: `git status --porcelain`
  2. Добавление измененных файлов в индекс: `git add -u`
  3. Коммит с кратким сообщением в формате Conventional Commits: `git commit -m "feat/fix: <действие>"`
  4. Отправка в удаленный репозиторий: `git push`
- Выводите только итоговый хеш коммита и краткий отчет о статусе.

## 5. Цикл проверки CI/CD после выполнения push
- После выполнения `git push` не считайте задачу сразу завершенной.
- Дождитесь завершения и отслеживайте статус выполнения рабочего процесса (workflow) с помощью GitHub CLI:
  `gh run list --limit 1`
  `gh run watch` (или используйте цикл ожидания/опроса до завершения).
- Если результат выполнения — «failure» (сбой):
  1. Автоматически получите логи сбоя: `gh run view --log-failed`
  2. Проанализируйте трассировку ошибки (последние 30 строк).
  3. Исправьте код локально.
  4. Выполните commit и снова сделайте push.
- Завершайте цикл и уведомляйте пользователя ТОЛЬКО при получении статуса «success» (успех) или после достижения лимита в 3 попытки.
